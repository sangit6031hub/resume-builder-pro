# ATS-Safe Resume Checklist (2026)

Several of the top results were low-quality or duplicated. I kept only the points that multiple sources agreed on and flagged where they conflict.

## 1. File
- [ ] **Format:** .docx is the safest choice, since some ATS may struggle to parse PDFs accurately. A text-based PDF (not a scan or image) is also widely accepted. Avoid older formats like .doc or .rtf.
- [ ] **Follow the job posting** if it names a format. Sources conflict here, and the posting's instruction overrides general advice.
- [ ] **Filename:** Use a simple name like "FirstName_LastName_Resume.docx" with no special characters.

## 2. Layout
- [ ] **Single column, left-aligned,** in reverse-chronological order. This is the format ATS software is built to parse.
- [ ] **No tables, text boxes, graphics or infographic skill bars.** They interrupt the left-to-right reading order parsers expect.
- [ ] **No headers or footers.** Many ATS ignore that content, so contact details placed there can appear missing. Put contact info in the body.
- [ ] **No icons** such as ☎ ✉ 🔗. Avoid these and fancy centering.
- [ ] **Fonts:** Arial, Calibri, Times New Roman or Verdana.
- [ ] **Sizes:** 10–12 pt body text and 14–16 pt headings.
- [ ] **Margins and color:** One-inch margins, black text, and at most a dark blue or gray for headings.

## 3. Structure and section headings
Use plain, standard headings: Work Experience, Education, Skills. Use "Work Experience", not something creative like "My Career Journey".

Recommended order:
1. Name, phone, email, LinkedIn/GitHub URL, location (city and state)
2. Professional Summary (3–4 lines, with the target job title mirrored honestly)
3. Skills
4. Work Experience
5. Projects (if relevant)
6. Education
7. Certifications

## 4. Content rules
- [ ] **Bullet formula:** action + scope + tools + impact. For example, "Reduced monthly close time 25% by automating reconciliations in Excel and SQL." Avoid vague lines like "Responsible for reporting."
- [ ] **Quantify results** with numbers, percentages, scale or time saved.
- [ ] **Keywords in context:** Pull the hard skills and tools from the job post, add the ones you truly have to Skills, and prove them in Experience or Projects bullets.
- [ ] **No keyword stuffing.** A skills section that is just a dump of every tool you've heard of is a red flag.
- [ ] **Job titles:** Use honest title variations that align with those in the job description.
- [ ] **Acronyms:** Include both the long form and the acronym, for example "Retrieval-Augmented Generation (RAG)".
- [ ] **Dates:** Use one consistent format such as "Jun 2020 - Present" or "06/2020 - Present", and avoid "Jun. 2020" or "2020/06". Inconsistent dates can make ATS miscalculate your experience.
- [ ] **Tailor** the resume to each job description.

## 5. Tailoring for an AI Engineer transition
With a long Java/Python/cloud background, use a hybrid structure. Career changers do best with skills and projects near the top, while still keeping a chronological Experience section.
- [ ] Put your AI/ML skills (Python, LLM APIs, RAG, vector databases, MLOps, cloud ML services) in Skills, but only those you can back up.
- [ ] Add a Projects section with 2–4 AI projects, each with stack, your role and a measurable result.
- [ ] Reword past bullets to highlight transferable work such as data pipelines, scalable services and cloud deployments.
- [ ] Mirror the target title (e.g., "AI Engineer") in your summary, but only where it is true.

## 6. Final tests (before submitting)
- [ ] **Copy/paste test:** Copy all the text into Notepad or TextEdit. It passes if sections stay in order, dates stay near roles, and bullets stay readable.
- [ ] Run the resume against the job description in a scanner like Jobscan. It gives a score and highlights missing keywords.
- [ ] Proofread for spelling and grammar, and confirm the links work.
- [ ] Check that the file is text-selectable and not an image.

**Caveat:** ATS behavior varies by employer and platform (Workday, Taleo, Greenhouse, Lever and others). No checklist guarantees a pass, so treat this as the safest common baseline.
